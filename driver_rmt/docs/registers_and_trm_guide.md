# Регістри, периферія та робота з Technical Reference Manual (TRM)

> Універсальний довідник. Застосовний до **будь-якого** модуля периферії, не лише RMT.
> Приклади наводяться на базі ESP32-S3, але підхід однаковий для будь-якого ARM/RISC-V мікроконтролера.

---

## 1. Що таке регістри

### Визначення

**Регістр** — це комірка пам'яті фіксованої ширини (зазвичай 32 біти), розташована **всередині апаратного модуля** мікроконтролера і відображена (mapped) в адресний простір процесора.

Кожен регістр має свою **фізичну адресу** в пам'яті. При записі значення за цією адресою відбувається не запис у звичайну RAM, а **пряме керування апаратурою**.

### Аналогія

Уявіть приладову панель літака. Кожен тумблер, перемикач та індикатор — це **один біт** у регістрі. Щоб увімкнути двигун, потрібно перемкнути конкретний тумблер (біт) у правильному регістрі. Порядок перемикання також важливий — спочатку паливо, потім запалювання.

### Типи регістрів за призначенням

| Тип                              | Що робить                        | Приклад                                              |
| -------------------------------- | -------------------------------- | ---------------------------------------------------- |
| **Конфігурації (Configuration)** | Задає режим роботи модуля        | `RMT_CH0CONF0_REG` — дільник частоти, розмір пам'яті |
| **Даних (Data)**                 | Читання/запис даних              | `RMT_CH0DATA_REG` — дані для передачі                |
| **Статусу (Status)**             | Читає поточний стан              | `RMT_INT_RAW_REG` — прапорці переривань              |
| **Керування (Control)**          | Запускає/зупиняє дію             | `TX_START`, `MEM_RD_RST` — старт передачі, скидання  |
| **Очищення (Clear)**             | Скидає прапорці                  | `RMT_INT_CLR_REG` — скидання прапорця переривання    |

### Типи доступу (як вказано в TRM)

В описі кожного біта в TRM вказано тип доступу. Це критично важливо:

| Позначення   | Розшифровка                      | Що означає                                                        |
| ------------ | -------------------------------- | ----------------------------------------------------------------- |
| **R/W**      | Read / Write                     | Можна читати і писати. Значення зберігається                      |
| **RO**       | Read Only                        | Тільки читання. Запис ігнорується                                 |
| **WO**       | Write Only                       | Тільки запис. Читання повертає 0                                  |
| **WT**       | Write Trigger                    | Запис 1 викликає дію, біт автоматично скидається в 0              |
| **R/WTC/SS** | Read / Write-to-Clear / Self-Set | Апаратура сама ставить 1. Щоб скинути — записуємо 1 в CLR-регістр |
| **R/W/SC**   | Read / Write / Self-Clear        | Запис 1 викликає дію, біт скидається апаратно                     |

> **Правило**: Перш ніж виконувати запис у біт, необхідно перевіряти його тип доступу. Спроба запису в RO-біт безглузда. Читання WT-біта завжди поверне 0.

### Memory-Mapped I/O (MMIO)

Процесор звертається до регістрів периферії **так само**, як до звичайної пам'яті — через читання/запис за адресою. Це називається **Memory-Mapped I/O**.

У ESP-IDF це робиться через макроси `REG_WRITE` та `REG_READ`:

```c
// Під капотом це volatile-вказівник на адресу в пам'яті:
#define REG_WRITE(addr, val)  (*(volatile uint32_t *)(addr) = (val))
#define REG_READ(addr)        (*(volatile uint32_t *)(addr))
```

**Навіщо `volatile`?** Без нього компілятор може «оптимізувати» читання/запис, вирішивши, що значення не змінюється. Але регістр — це апаратура: його значення може змінитися в будь-який момент (наприклад, прапорець переривання встановлюється залізом). `volatile` забороняє компілятору такі оптимізації.

## 2. Що таке периферія (Peripherals)

### Визначення

**Периферія** — це апаратні модулі всередині мікроконтролера, кожен з яких вирішує конкретне завдання **автономно від CPU**.

CPU лише **налаштовує** модуль через регістри та **запускає** його. Після цього модуль працює самостійно, а CPU може займатися іншими справами.

### Приклади периферійних модулів

| Модуль      | Призначення                                              |
| ----------- | -------------------------------------------------------- |
| **GPIO**    | Введення/виведення цифрових сигналів                     |
| **UART**    | Послідовний зв'язок (Serial)                             |
| **SPI**     | Швидкий синхронний інтерфейс (дисплеї, SD, Flash)        |
| **I2C**     | Двопровідна шина (датчики, EEPROM)                       |
| **RMT**     | Генерація/прийом імпульсних послідовностей (LED, ІЧ)     |
| **Timer**   | Апаратні таймери та лічильники                           |
| **ADC/DAC** | Аналогово-цифрове та цифро-аналогове перетворення        |
| **DMA**     | Прямий доступ до пам'яті без участі CPU                  |

### Як периферія підключена всередині MCU

```
┌─────────────────────────────────────────────┐
│                   MCU (SoC)                 │
│                                             │
│   ┌───────┐         ┌──────────────────┐    │
│   │  CPU  │◄───────►│ Системна шина    │    │
│   │(Xtensa│         │     (APB/AHB)    │    │
│   │/RISCV)│         └──────┬───────────┘    │
│   └───────┘                │                │
│                    ┌───────┼───────┐        │
│                    ▼       ▼       ▼        │
│                 ┌─────┐ ┌─────┐ ┌─────┐     │
│                 │ RMT │ │UART │ │ SPI │     │
│                 │     │ │     │ │     │     │
│                 └──┬──┘ └──┬──┘ └──┬──┘     │
│                    │       │       │        │
│ ═══════════════════╧═══════╧═══════╧════    │ ← GPIO Matrix / IO MUX
│                    │       │       │        │
└────────────────────┼───────┼───────┼────────┘
                     ▼       ▼       ▼
                   Піни мікроконтролера
```

### Тактування (Clocking)

Кожен периферійний модуль за замовчуванням **вимкнений** для економії енергії. Щоб почати роботу з модулем, потрібно:

1. **Увімкнути тактування** — подати тактовий сигнал на модуль через системний регістр
2. **Зняти скидання** — вивести модуль зі стану reset

```c
// Приклад для RMT на ESP32-S3:
// 1. Вмикаємо тактовий сигнал
REG_WRITE(SYSTEM_PERIP_CLK_EN0_REG,
          REG_READ(SYSTEM_PERIP_CLK_EN0_REG) | SYSTEM_RMT_CLK_EN);

// 2. Знімаємо скидання (очищаємо біт скидання)
REG_WRITE(SYSTEM_PERIP_RST_EN0_REG,
          REG_READ(SYSTEM_PERIP_RST_EN0_REG) & ~SYSTEM_RMT_RST);
```

> **Без увімкненого тактування всі записи в регістри модуля будуть проігноровані.** Це найчастіша причина, коли «нічого не працює, хоча все правильно налаштовано».

## 3. Бітові операції: мова спілкування з регістрами

Регістр — це 32 біти. Кожен біт або група бітів відповідає за свою функцію. Щоб змінювати окремі біти, не чіпаючи інші, використовуються **бітові операції**.

### Основні патерни

#### SET — встановити біт в 1 (увімкнути)

```c
// Увімкнути біт 6 (IDLE_OUT_EN)
reg |= (1 << 6);
//       ┗━ зсуваємо одиницю на позицію 6
// |= означає: залишити всі інші біти як були, а біт 6 поставити в 1
```

#### CLEAR — скинути біт в 0 (вимкнути)

```c
// Вимкнути біт 5 (IDLE_OUT_LV)
reg &= ~(1 << 5);
//   ~  = інвертувати (всі біти в 1, крім 5-го)
//   &= = залишити тільки ті біти, які були І в масці
// Результат: біт 5 обнуляється, інші не змінюються
```

#### READ — прочитати значення біта

```c
// Перевірити, чи встановлено біт 0 (TX_END)
if (REG_READ(RMT_INT_RAW_REG) & (1 << 0)) {
    // Передача завершена
}
```

#### MODIFY — змінити групу бітів (очистити поле, потім записати нове значення)

```c
// Записати дільник у біти [15:8] (поле шириною 8 біт)

// Крок 1: Очищаємо поле
reg &= ~(0xFF << 8);   // 0xFF = 8 одиниць = маска шириною 8 біт
                        // Зсуваємо на позицію 8
                        // Інвертуємо та застосовуємо AND

// Крок 2: Записуємо нове значення
reg |= (div << 8);     // Зсуваємо значення на позицію 8 та застосовуємо OR
```

### Як читати маски у заголовковому файлі

У ESP-IDF кожен біт/поле описано набором макросів. Приклад для `RMT_DIV_CNT_CH0`:

```c
#define RMT_DIV_CNT_CH0    0x000000FFU   // Маска значення (8 біт = 0xFF)
#define RMT_DIV_CNT_CH0_M  (RMT_DIV_CNT_CH0_V << RMT_DIV_CNT_CH0_S)  // Маска зі зсувом
#define RMT_DIV_CNT_CH0_V  0x000000FFU   // Маска значення (те саме, що основний)
#define RMT_DIV_CNT_CH0_S  8             // Позиція зсуву (біт 8)
```

| Суфікс       | Значення                               | Як використовувати                               |
| ------------ | -------------------------------------- | ------------------------------------------------ |
| `_M` (Mask)  | Маска, вже зсунута на потрібну позицію | Для очищення: `reg &= ~RMT_DIV_CNT_CH0_M`        |
| `_V` (Value) | Маска значення без зсуву               | Для перевірки діапазону                          |
| `_S` (Shift) | Позиція молодшого біта поля            | Для запису: `reg \|= (val << RMT_DIV_CNT_CH0_S)` |

> **Порада**: Для початкового розуміння рекомендується використовувати «сирі» числа `(0xFF << 8)`. У production-коді слід використовувати макроси `_M`, `_S` — це робить код самодокументованим та портативним.

## 4. Флоу роботи з Technical Reference Manual (TRM)

Це **головний розділ**. Тут описано покроковий алгоритм, як від «мені потрібна периферія X» дійти до працюючого коду.

### Крок 1: Відкрий TRM і знайди розділ модуля

TRM — це документ на 700-1500 сторінок. Читання всього документа не потрібне. Пошук потрібного модуля здійснюється через зміст.

Приклад: потрібен RMT → шукаєш **"Chapter N: Remote Control Peripheral (RMT)"**.

### Крок 2: Прочитай Overview

Перші 1-2 сторінки глави. У цьому розділі міститься інформація:

- **Що** модуль робить (призначення)
- **Скільки** каналів / екземплярів
- **Які** основні можливості (TX, RX, carrier modulation, DMA)

> Приклад: з Overview RMT стає відомо, що в ESP32-S3 є 4 TX-канали і 4 RX-канали, модуль може генерувати і приймати імпульсні послідовності з програмованою роздільною здатністю.

### Крок 3: Вивчи Functional Description (архітектура)

Тут буде **блок-схема** модуля. Це ключ до розуміння:

- Звідки модуль бере дані (RAM, FIFO, DMA)
- Як влаштований ланцюжок тактування (джерело → дільники → вихід)
- Які внутрішні підблоки існують (TX engine, RX engine, carrier modulator)

```
 ┌──────────────────────────────────────────────────────┐
 │               Що шукати у блок-схемі                 │
 ├──────────────────────────────────────────────────────┤
 │  1. Джерела тактування (clock sources)               │
 │  2. Дільники частоти (prescalers/dividers)           │
 │  3. Буфери даних (RAM/FIFO)                          │
 │  4. Мультиплексори (вибір режиму)                    │
 │  5. Виходи/входи модуля (до GPIO matrix)             │
 └──────────────────────────────────────────────────────┘
```

### Крок 4: Знайди розділ Register Summary

Таблиця з **усіма** регістрами модуля. Вона містить:

- Ім'я регістра
- Адреса (зсув від базової адреси)
- Короткий опис

Це «карта навігації». Запам'ятовування всіх регістрів не потрібне — важливо розуміти структуру груп:

- **Конфігурація каналів** (`CHnCONF0`, `CHnCONF1`)
- **Дані** (`CHnDATA`)
- **Переривання** (`INT_RAW`, `INT_ST`, `INT_ENA`, `INT_CLR`)
- **Системна конфігурація** (`SYS_CONF`)

### Крок 5: Розбери кожен потрібний регістр побітово

В описі конкретного регістра для кожного біта/поля вказано:

- **Ім'я** (наприклад, `DIV_CNT_CH0`)
- **Позиція** (bitpos: `[15:8]`)
- **Тип доступу** (R/W, WT, RO)
- **Значення за замовчуванням** (default)
- **Опис** — що цей біт/поле робить

### Крок 6: Визнач порядок увімкнення

**Це найважливіше.** Порядок налаштування регістрів зазвичай такий:

```
┌─────────────────────────────────────────────────────────────┐
│         УНІВЕРСАЛЬНИЙ ПОРЯДОК НАЛАШТУВАННЯ ПЕРИФЕРІЇ        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① Системне тактування                                     │
│     Увімкнути тактовий сигнал на рівні системи.             │
│     Зняти апаратне скидання модуля.                         │
│     Регістри: SYSTEM_PERIP_CLK_EN0_REG,                     │
│               SYSTEM_PERIP_RST_EN0_REG                      │
│                                                             │
│  ② Маршрутизація GPIO                                      │
│     Підключити вхід/вихід модуля до фізичного піна.         │

│  ④ Конфігурація каналу/модуля                              │
│     Налаштувати дільник частоти.                            │
│     Задати розмір буфера.                                   │
│     Вибрати режим роботи (continuous, wrap, one-shot).      │
│     Налаштувати поведінку виходу в IDLE.                    │
│     Скинути вказівники пам'яті.                             │
│     Регістри: CHnCONF0, CHnCONF1                            │
│                                                             │
│  ⑤ Защіпка конфігурації (CONF_UPDATE)                      │
│     Записати спеціальний біт, щоб апаратура                 │
│     «підхопила» всі налаштування.                           │
│     НЕ ВСІ модулі вимагають цього кроку —                   │
│     перевіряй у TRM!                                        │
│                                                             │
│  ⑥ Завантаження даних                                      │
│     Записати дані в буфер/FIFO модуля.                      │
│     Регістр: CHnDATA або адреса RAM                         │
│                                                             │
│  ⑦ Старт                                                   │
│     Встановити біт запуску.                                 │
│     Регістр: TX_START, RX_START, або аналог                 │
│                                                             │
│  ⑧ Очікування завершення                                   │
│     Polling: читати INT_RAW_REG до появи прапорця.          │
│     Або: налаштувати переривання і чекати через RTOS.       │
│                                                             │
│  ⑨ Очищення прапорців                                      │
│     Записати 1 у відповідний біт INT_CLR_REG.               │
│     НІКОЛИ не писати 0 в INT_RAW — це не працює.            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Як визначити правильний порядок за документацією

1. **Шукай розділ «Programming Procedure»** або **«Functional Description»** у главі модуля. Там часто є явний список кроків.
2. **Якщо явного списку немає** — слідуй логіці:
   - Спочатку подай живлення/тактування (без цього модуль не «чує» записи)
   - Потім налаштуй основні параметри
   - В кінці — запусти
3. **Звертай увагу на примітки** (Notes/Warnings) в TRM. Там часто вказано: «Bit X must be set **before** Bit Y».

## 5. Защіпка конфігурації (CONF_UPDATE)

Деякі модулі використовують механізм **синхронізації конфігурації**. Суть:

- Запис налаштувань здійснюється в регістри, але апаратура **не застосовує** їх негайно
- Для застосування необхідно записати 1 у спеціальний біт `CONF_UPDATE`
- Апаратура «защіпає» (latch) усі налаштування атомарно

```c
// Приклад: після всіх налаштувань RMT каналу 0
ch0conf0 |= (1 << 24);                    // RMT_CONF_UPDATE_CH0
REG_WRITE(RMT_CH0CONF0_REG, ch0conf0);    // Защіпка!
```

**Навіщо це потрібно?** Без защіпки апаратура могла б «побачити» половину налаштувань — наприклад, новий дільник, але старий розмір пам'яті. Защіпка гарантує, що всі налаштування застосовуються одночасно.

> **Важливо**: Біт `CONF_UPDATE` — це біт типу **WT** (Write Trigger). Він автоматично скидається після запису. Його встановлення вимагається **кожен раз**, коли необхідно застосувати зміни.

## 6. Переривання: як дізнатися, що модуль закінчив роботу

Типова архітектура переривань в ESP32-S3:

| Регістр   | Тип      | Призначення                                    |
| --------- | -------- | ---------------------------------------------- |
| `INT_RAW` | R/WTC/SS | «Сирі» прапорці. Залізо ставить 1 при події    |
| `INT_ST`  | RO       | Маскований статус (RAW & ENA)                  |
| `INT_ENA` | R/W      | Маска дозволу переривань                       |
| `INT_CLR` | WT       | Запис 1 скидає відповідний прапорець у RAW     |

### Polling (простий спосіб)

```c
// Чекаємо завершення передачі (біт 0 = CH0_TX_END)
while ((REG_READ(RMT_INT_RAW_REG) & (1 << 0)) == 0) {
    // Крутимось у порожньому циклі
}
// Скидаємо прапорець через CLR-регістр
REG_WRITE(RMT_INT_CLR_REG, (1 << 0));
```

### Interrupt (production-спосіб)

У реальному проєкті замість polling використовують FreeRTOS:

1. Налаштовують `INT_ENA` для потрібної події
2. Реєструють ISR-обробник
3. У ISR віддають семафор
4. Задача чекає на семафорі (і не витрачає CPU)

## 7. Типові граблі та як їх уникнути

### ❌ «Пишу в регістри — нічого не відбувається»

**Причина**: Не увімкнено тактування на системному рівні.
**Рішення**: Завжди починай з `SYSTEM_PERIP_CLK_EN0_REG` + `SYSTEM_PERIP_RST_EN0_REG`.

### ❌ «Налаштував, але модуль працює зі старими параметрами»

**Причина**: Забув записати `CONF_UPDATE`.
**Рішення**: Після кожного блоку налаштувань — защіпка.

### ❌ «Прапорець переривання не скидається»

**Причина**: Намагаєшся писати 0 в `INT_RAW_REG`.
**Рішення**: Прапорці скидаються **тільки** через `INT_CLR_REG`, і **тільки** записом 1.

### ❌ «Дані перезаписуються / не передаються повністю»

**Причина**: Не скинуто вказівник запису/читання перед завантаженням даних.
**Рішення**: Перед записом даних завжди роби `APB_MEM_RST` → `CONF_UPDATE`, потім знімай reset.

### ❌ «Змінив одне поле — зламалися інші налаштування»

**Причина**: Записав у регістр ціле число замість bitwise-операції.
**Рішення**: Завжди використовуй read-modify-write: `REG_READ` → зміна бітів → `REG_WRITE`.

### ❌ «Макрос із заголовкового файлу не працює як очікувалося»

**Причина**: Переплутав `_M` (маска зі зсувом) та `_S` (позиція зсуву).
**Рішення**: `_M` — для очищення (`&= ~_M`), `_S` — для запису значення (`|= val << _S`).
