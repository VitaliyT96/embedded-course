# Регистры, периферия и работа с Technical Reference Manual (TRM)

> Универсальный справочник. Применим к **любому** модулю периферии, не только RMT.
> Примеры приводятся на базе ESP32-S3, но подход одинаков для любого ARM/RISC-V микроконтроллера.

---

## 1. Что такое регистры

### Определение

**Регистр** — это ячейка памяти фиксированной ширины (обычно 32 бита), расположенная **внутри аппаратного модуля** микроконтроллера и отображённая (mapped) в адресное пространство процессора.

Каждый регистр имеет свой **физический адрес** в памяти. При записи значения по этому адресу происходит не запись в обычную RAM, а **напрямое управление аппаратурой**.

### Аналогия

Представь приборную панель самолёта. Каждый тумблер, переключатель и индикатор — это **один бит** в регистре. Чтобы включить двигатель, нужно переключить конкретный тумблер (бит) в правильном регистре. Порядок переключения тоже важен — сначала топливо, потом зажигание.

### Типы регистров по назначению

| Тип                              | Что делает                       | Пример                                               |
| -------------------------------- | -------------------------------- | ---------------------------------------------------- |
| **Конфигурации (Configuration)** | Задаёт режим работы модуля       | `RMT_CH0CONF0_REG` — делитель частоты, размер памяти |
| **Данных (Data)**                | Чтение/запись данных             | `RMT_CH0DATA_REG` — данные для передачи              |
| **Статуса (Status)**             | Читает текущее состояние         | `RMT_INT_RAW_REG` — флаги прерываний                 |
| **Управления (Control)**         | Запускает/останавливает действие | `TX_START`, `MEM_RD_RST` — старт передачи, сброс     |
| **Очистки (Clear)**              | Сбрасывает флаги                 | `RMT_INT_CLR_REG` — сброс флага прерывания           |

### Типы доступа (как указано в TRM)

В описании каждого бита в TRM указан тип доступа. Это критически важно:

| Обозначение  | Расшифровка                      | Что значит                                                        |
| ------------ | -------------------------------- | ----------------------------------------------------------------- |
| **R/W**      | Read / Write                     | Можно читать и писать. Значение сохраняется                       |
| **RO**       | Read Only                        | Только чтение. Запись игнорируется                                |
| **WO**       | Write Only                       | Только запись. Чтение возвращает 0                                |
| **WT**       | Write Trigger                    | Запись 1 вызывает действие, бит автоматически сбрасывается в 0    |
| **R/WTC/SS** | Read / Write-to-Clear / Self-Set | Аппаратура сама ставит 1. Чтобы сбросить — пишешь 1 в CLR-регистр |
| **R/W/SC**   | Read / Write / Self-Clear        | Запись 1 вызывает действие, бит сбрасывается аппаратно            |

> **Правило**: Прежде чем выполнять запись в бит, необходимо проверять его тип доступа. Попытка записи в RO-бит бессмысленна. Чтение WT-бита всегда вернёт 0.

### Memory-Mapped I/O (MMIO)

Процессор обращается к регистрам периферии **точно так же**, как к обычной памяти — через чтение/запись по адресу. Это называется **Memory-Mapped I/O**.

В ESP-IDF это делается через макросы `REG_WRITE` и `REG_READ`:

```c
// Под капотом это volatile-указатель на адрес в памяти:
#define REG_WRITE(addr, val)  (*(volatile uint32_t *)(addr) = (val))
#define REG_READ(addr)        (*(volatile uint32_t *)(addr))
```

**Зачем `volatile`?** Без него компилятор может «оптимизировать» чтение/запись, решив, что значение не меняется. Но регистр — это аппаратура: его значение может измениться в любой момент (например, флаг прерывания устанавливается железом). `volatile` запрещает компилятору такие оптимизации.

## 2. Что такое периферия (Peripherals)

### Определение

**Периферия** — это аппаратные модули внутри микроконтроллера, каждый из которых решает конкретную задачу **автономно от CPU**.

CPU лишь **настраивает** модуль через регистры и **запускает** его. После этого модуль работает самостоятельно, а CPU может заниматься другими делами.

### Примеры периферийных модулей

| Модуль      | Назначение                                               |
| ----------- | -------------------------------------------------------- |
| **GPIO**    | Ввод/вывод цифровых сигналов                             |
| **UART**    | Последовательная связь (Serial)                          |
| **SPI**     | Быстрый синхронный интерфейс (дисплеи, SD, Flash)        |
| **I2C**     | Двухпроводная шина (датчики, EEPROM)                     |
| **RMT**     | Генерация/приём импульсных последовательностей (LED, ИК) |
| **Timer**   | Аппаратные таймеры и счётчики                            |
| **ADC/DAC** | Аналого-цифровое и цифро-аналоговое преобразование       |
| **DMA**     | Прямой доступ к памяти без участия CPU                   |

### Как периферия подключена внутри MCU

```
┌─────────────────────────────────────────────┐
│                   MCU (SoC)                 │
│                                             │
│   ┌───────┐         ┌──────────────────┐    │
│   │  CPU  │◄───────►│  Системная шина  │    │
│   │(Xtensa│         │     (APB/AHB)    │    │
│   │/RISCV)│         └──────┬───────────┘    │
│   └───────┘                │                │
│                    ┌───────┼───────┐        │
│                    ▼       ▼       ▼        │
│                 ┌─────┐ ┌─────┐ ┌─────┐     │
│                 │ RMT │ │UART │ │ SPI │     │
│                 │     │ │     │ │     │     │
│                 └──┬──┘ └──┬──┘ └──┬──┘     │
│                    │       │       │        │
│ ═══════════════════╧═══════╧═══════╧════    │ ← GPIO Matrix / IO MUX
│                    │       │       │        │
└────────────────────┼───────┼───────┼────────┘
                     ▼       ▼       ▼
                   Пины микроконтроллера
```

### Тактирование (Clocking)

Каждый периферийный модуль по умолчанию **отключён** для экономии энергии. Чтобы начать работу с модулем, нужно:

1. **Включить тактирование** — подать тактовый сигнал на модуль через системный регистр
2. **Снять сброс** — вывести модуль из состояния reset

```c
// Пример для RMT на ESP32-S3:
// 1. Включаем тактовый сигнал
REG_WRITE(SYSTEM_PERIP_CLK_EN0_REG,
          REG_READ(SYSTEM_PERIP_CLK_EN0_REG) | SYSTEM_RMT_CLK_EN);

// 2. Снимаем сброс (очищаем бит сброса)
REG_WRITE(SYSTEM_PERIP_RST_EN0_REG,
          REG_READ(SYSTEM_PERIP_RST_EN0_REG) & ~SYSTEM_RMT_RST);
```

> **Без включённого тактирования все записи в регистры модуля будут проигнорированы.** Это самая частая причина, когда «ничего не работает, хотя всё правильно настроено».

## 3. Битовые операции: язык общения с регистрами

Регистр — это 32 бита. Каждый бит или группа битов отвечает за свою функцию. Чтобы менять отдельные биты, не трогая остальные, используются **битовые операции**.

### Основные паттерны

#### SET — установить бит в 1 (включить)

```c
// Включить бит 6 (IDLE_OUT_EN)
reg |= (1 << 6);
//       ┗━ сдвигаем единицу на позицию 6
// |= означает: оставить все остальные биты как были, а бит 6 поставить в 1
```

#### CLEAR — сбросить бит в 0 (выключить)

```c
// Выключить бит 5 (IDLE_OUT_LV)
reg &= ~(1 << 5);
//   ~  = инвертировать (все биты в 1, кроме 5-го)
//   &= = оставить только те биты, которые были И в маске
// Результат: бит 5 обнуляется, остальные не меняются
```

#### READ — прочитать значение бита

```c
// Проверить, установлен ли бит 0 (TX_END)
if (REG_READ(RMT_INT_RAW_REG) & (1 << 0)) {
    // Передача завершена
}
```

#### MODIFY — изменить группу битов (очистить поле, затем записать новое значение)

```c
// Записать делитель в биты [15:8] (поле шириной 8 бит)

// Шаг 1: Очищаем поле
reg &= ~(0xFF << 8);   // 0xFF = 8 единиц = маска шириной 8 бит
                        // Сдвигаем на позицию 8
                        // Инвертируем и применяем AND

// Шаг 2: Записываем новое значение
reg |= (div << 8);     // Сдвигаем значение на позицию 8 и OR-им
```

### Как читать маски в заголовочном файле

В ESP-IDF каждый бит/поле описан набором макросов. Пример для `RMT_DIV_CNT_CH0`:

```c
#define RMT_DIV_CNT_CH0    0x000000FFU   // Маска значения (8 бит = 0xFF)
#define RMT_DIV_CNT_CH0_M  (RMT_DIV_CNT_CH0_V << RMT_DIV_CNT_CH0_S)  // Маска со сдвигом
#define RMT_DIV_CNT_CH0_V  0x000000FFU   // Маска значения (то же, что основной)
#define RMT_DIV_CNT_CH0_S  8             // Позиция сдвига (бит 8)
```

| Суффикс      | Значение                               | Как использовать                                 |
| ------------ | -------------------------------------- | ------------------------------------------------ |
| `_M` (Mask)  | Маска, уже сдвинутая на нужную позицию | Для очистки: `reg &= ~RMT_DIV_CNT_CH0_M`         |
| `_V` (Value) | Маска значения без сдвига              | Для проверки диапазона                           |
| `_S` (Shift) | Позиция младшего бита поля             | Для записи: `reg \|= (val << RMT_DIV_CNT_CH0_S)` |

> **Совет**: Для начального понимания рекомендуется использовать «сырые» числа `(0xFF << 8)`. В production-коде следует использовать макросы `_M`, `_S` — это делает код самодокументируемым и переносимым.

## 4. Флоу работы с Technical Reference Manual (TRM)

Это **главный раздел**. Здесь описан пошаговый алгоритм, как от «мне нужна периферия X» дойти до работающего кода.

### Шаг 1: Открой TRM и найди раздел модуля

TRM — это документ на 700-1500 страниц. Чтение всего документа не требуется. Поиск нужного модуля осуществляется через оглавление.

Пример: нужен RMT → ищешь **"Chapter N: Remote Control Peripheral (RMT)"**.

### Шаг 2: Прочитай Overview

Первые 1-2 страницы главы. Здесь ты узнаешь:

- **Что** модуль делает (назначение)
- **Сколько** каналов / экземпляров
- **Какие** основные возможности (TX, RX, carrier modulation, DMA)

> Пример: из Overview RMT становится известно, что в ESP32-S3 есть 4 TX-канала и 4 RX-канала, модуль может генерировать и принимать импульсные последовательности с программируемым разрешением.

### Шаг 3: Изучи Functional Description (архитектура)

Здесь будет **блок-схема** модуля. Это ключ к пониманию:

- Откуда модуль берёт данные (RAM, FIFO, DMA)
- Как устроена цепочка тактирования (источник → делители → выход)
- Какие внутренние подблоки есть (TX engine, RX engine, carrier modulator)

```
 ┌──────────────────────────────────────────────────────┐
 │               Что искать в блок-схеме                │
 ├──────────────────────────────────────────────────────┤
 │  1. Источники тактирования (clock sources)           │
 │  2. Делители частоты (prescalers/dividers)           │
 │  3. Буферы данных (RAM/FIFO)                         │
 │  4. Мультиплексоры (выбор режима)                    │
 │  5. Выходы/входы модуля (к GPIO matrix)              │
 └──────────────────────────────────────────────────────┘
```

### Шаг 4: Найди раздел Register Summary

Таблица со **всеми** регистрами модуля. Она содержит:

- Имя регистра
- Адрес (смещение от базового адреса)
- Краткое описание

Это «карта навигации». Запоминание всех регистров не требуется — важно понимать структуру групп:

- **Конфигурация каналов** (`CHnCONF0`, `CHnCONF1`)
- **Данные** (`CHnDATA`)
- **Прерывания** (`INT_RAW`, `INT_ST`, `INT_ENA`, `INT_CLR`)
- **Системная конфигурация** (`SYS_CONF`)

### Шаг 5: Разбери каждый нужный регистр побитово

В описании конкретного регистра для каждого бита/поля указано:

- **Имя** (например, `DIV_CNT_CH0`)
- **Позиция** (bitpos: `[15:8]`)
- **Тип доступа** (R/W, WT, RO)
- **Значение по умолчанию** (default)
- **Описание** — что этот бит/поле делает

### Шаг 6: Определи порядок включения

**Это самое важное.** Порядок настройки регистров обычно такой:

```
┌─────────────────────────────────────────────────────────────┐
│         УНИВЕРСАЛЬНЫЙ ПОРЯДОК НАСТРОЙКИ ПЕРИФЕРИИ           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① Системное тактирование                                  │
│     Включить тактовый сигнал на уровне системы.             │
│     Снять аппаратный сброс модуля.                          │
│     Регистры: SYSTEM_PERIP_CLK_EN0_REG,                     │
│               SYSTEM_PERIP_RST_EN0_REG                      │
│                                                             │
│  ② Маршрутизация GPIO                                      │
│     Подключить вход/выход модуля к физическому пину.        │
│     Настроить направление пина (вход/выход).                │
│     Функции: gpio_pad_select, gpio_set_direction,           │
│              gpio_connect_out_signal                        │
│                                                             │
│  ③ Тактирование модуля                                      │
│     Выбрать источник частоты (APB, XTAL, RC).               │
│     Включить внутренний clock gate.                         │
│     Настроить режим доступа к памяти (FIFO/direct).         │
│     Регистр: MODULE_SYS_CONF_REG или аналог                │

│     Настроить делитель частоты.                              │
│     Задать размер буфера.                                   │
│     Выбрать режим работы (continuous, wrap, one-shot).       │
│     Настроить поведение выхода в IDLE.                      │
│     Сбросить указатели памяти.                              │
│     Регистры: CHnCONF0, CHnCONF1                            │
│                                                             │
│  ⑤ Защёлка конфигурации (CONF_UPDATE)                       │
│     Записать специальный бит, чтобы аппаратура              │
│     «подхватила» все настройки.                             │
│     НЕ ВСЕ модули требуют этого шага —                      │
│     проверяй в TRM!                                         │
│                                                             │
│  ⑥ Загрузка данных                                          │
│     Записать данные в буфер/FIFO модуля.                    │
│     Регистр: CHnDATA или адрес RAM                          │
│                                                             │
│  ⑦ Старт                                                    │
│     Установить бит запуска.                                  │
│     Регистр: TX_START, RX_START, или аналог                 │
│                                                             │
│  ⑧ Ожидание завершения                                      │
│     Polling: читать INT_RAW_REG до появления флага.         │
│     Или: настроить прерывание и ждать через RTOS.           │
│                                                             │
│  ⑨ Очистка флагов                                           │
│     Записать 1 в соответствующий бит INT_CLR_REG.           │
│     НИКОГДА не писать 0 в INT_RAW — это не работает.        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Как определить правильный порядок по документации

1. **Ищи раздел «Programming Procedure»** или **«Functional Description»** в главе модуля. Там часто есть явный список шагов.
2. **Если явного списка нет** — следуй логике:
   - Сначала подай питание/тактирование (без этого модуль не «слышит» записи)
   - Потом настрой основные параметры
   - В конце — запусти
3. **Обращай внимание на примечания** (Notes/Warnings) в TRM. Там часто указано: «Bit X must be set **before** Bit Y».

## 5. Защёлка конфигурации (CONF_UPDATE)

Некоторые модули используют механизм **синхронизации конфигурации**. Суть:

- Запись настроек производится в регистры, но аппаратура **не применяет** их немедленно
- Для применения необходимо записать 1 в специальный бит `CONF_UPDATE`
- Аппаратура «защёлкивает» (latch) все настройки атомарно

```c
// Пример: после всех настроек RMT канала 0
ch0conf0 |= (1 << 24);                    // RMT_CONF_UPDATE_CH0
REG_WRITE(RMT_CH0CONF0_REG, ch0conf0);    // Защёлка!
```

**Зачем это нужно?** Без защёлки аппаратура могла бы «увидеть» половину настроек — например, новый делитель, но старый размер памяти. Защёлка гарантирует, что все настройки применяются одновременно.

> **Важно**: Бит `CONF_UPDATE` — это бит типа **WT** (Write Trigger). Он автоматически сбрасывается после записи. Его установка требуется **каждый раз**, когда необходимо применить изменения.

## 6. Прерывания: как узнать, что модуль закончил работу

Типичная архитектура прерываний в ESP32-S3:

| Регистр   | Тип      | Назначение                                     |
| --------- | -------- | ---------------------------------------------- |
| `INT_RAW` | R/WTC/SS | «Сырые» флаги. Железо ставит 1 при событии     |
| `INT_ST`  | RO       | Маскированный статус (RAW & ENA)               |
| `INT_ENA` | R/W      | Маска разрешения прерываний                    |
| `INT_CLR` | WT       | Запись 1 сбрасывает соответствующий флаг в RAW |

### Polling (простой способ)

```c
// Ждём завершения передачи (бит 0 = CH0_TX_END)
while ((REG_READ(RMT_INT_RAW_REG) & (1 << 0)) == 0) {
    // Крутимся в пустом цикле
}
// Сбрасываем флаг через CLR-регистр
REG_WRITE(RMT_INT_CLR_REG, (1 << 0));
```

### Interrupt (production-способ)

В реальном проекте вместо polling используют FreeRTOS:

1. Настраивают `INT_ENA` для нужного события
2. Регистрируют ISR-обработчик
3. В ISR отдают семафор
4. Задача ждёт на семафоре (и не тратит CPU)

## 7. Типичные грабли и как их избежать

### ❌ «Пишу в регистры — ничего не происходит»

**Причина**: Не включено тактирование на системном уровне.
**Решение**: Всегда начинай с `SYSTEM_PERIP_CLK_EN0_REG` + `SYSTEM_PERIP_RST_EN0_REG`.

### ❌ «Настроил, но модуль работает со старыми параметрами»

**Причина**: Забыл записать `CONF_UPDATE`.
**Решение**: После каждого блока настроек — защёлка.

### ❌ «Флаг прерывания не сбрасывается»

**Причина**: Пытаешься писать 0 в `INT_RAW_REG`.
**Решение**: Флаги сбрасываются **только** через `INT_CLR_REG`, и **только** записью 1.

### ❌ «Данные перезаписываются / не передаются полностью»

**Причина**: Не сброшен указатель записи/чтения перед загрузкой данных.
**Решение**: Перед записью данных всегда делай `APB_MEM_RST` → `CONF_UPDATE`, затем снимай reset.

### ❌ «Изменил одно поле — сломались другие настройки»

**Причина**: Записал в регистр целое число вместо bitwise-операции.
**Решение**: Всегда используй read-modify-write: `REG_READ` → изменение битов → `REG_WRITE`.

### ❌ «Макрос из заголовочного файла не работает как ожидалось»

**Причина**: Перепутал `_M` (маска со сдвигом) и `_S` (позиция сдвига).
**Решение**: `_M` — для очистки (`&= ~_M`), `_S` — для записи значения (`|= val << _S`).
