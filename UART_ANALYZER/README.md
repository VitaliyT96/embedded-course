# Програмний UART (TX) через RMT

Цей навчальний проєкт демонструє, як реалізувати програмний (Software) UART передавач (TX) на ESP32 за допомогою периферії **RMT (Remote Control Transceiver)**, використовуючи драйвер `rmt_raw`, написаний на регістрах.

## Чому саме RMT для Software UART?

Апаратний UART у мікроконтролері ESP32 — це чудова річ, але його кількість обмежена. Якщо вам потрібен додатковий UART порт тільки для передачі (TX), периферія RMT ідеально для цього підходить. 
RMT вміє з високою точністю генерувати імпульси довільної довжини апаратно. Нам достатньо лише "спакувати" біти UART у формат RMT (вказавши тривалість та рівень кожного біта), і апаратна частина сама "виштовхне" їх на пін з ідеальними таймінгами, не завантажуючи CPU.

## Формат кадру UART (Frame)

Класичний кадр UART (формат 8N1) складається з 10 біт:
1. **Start bit** — завжди `0` (LOW). Сигналізує про початок передачі.
2. **Data bits** — 8 біт даних, починаючи з молодшого (LSB first).
3. **Stop bit** — завжди `1` (HIGH). Завершує передачу.

У стані спокою (Idle) лінія UART завжди підтягнута до логічної одиниці (`1`, HIGH).

## Як ми упаковуємо біти для RMT

Драйвер RMT очікує дані у вигляді масиву структур `rmt_item_t`. Одна така структура описує **два стани (два біти)**:
```c
typedef struct {
    uint16_t dur0; // Тривалість 1-го стану
    uint16_t lvl0; // Рівень 1-го стану (0 або 1)
    uint16_t dur1; // Тривалість 2-го стану
    uint16_t lvl1; // Рівень 2-го стану (0 або 1)
} rmt_item_t;
```

Оскільки UART-кадр має 10 біт, а один `rmt_item_t` вміщує 2 біти, нам потрібен масив із **5 елементів** `rmt_item_t`.

### Логіка пакування (bit-packing) у `sw_uart_tx_byte`
Щоб не заплутатися в індексах, ми розділили логіку на два незалежних блоки: один для парних бітів (lvl0), інший для непарних (lvl1).

- **Індекс 0 (Start bit)**: Завжди 0. Призначається у `lvl0` першого елемента `frame[0]`.
- **Індекси 1..8 (Data bits)**: Витягуються з байта даних за допомогою побітового зсуву: `(data >> (idx - 1)) & 1`. Вони потрапляють у відповідні `lvl0` та `lvl1`.
- **Індекс 9 (Stop bit)**: Завжди 1. Призначається у `lvl1` останнього елемента `frame[4]`.

Усі тривалості (`dur0` і `dur1`) встановлюються однаковими і дорівнюють тривалості одного біта (для швидкості 9600 бод при тактуванні 1 МГц це `104` мікросекунди).

## Проблеми, з якими ми зіткнулися (і як їх вирішили)

У процесі розробки та налагодження за допомогою логічного аналізатора ми виявили кілька цікавих нюансів у драйвері `rmt_raw`, який писався раніше:

### 1. Помилка базової частоти RMT на ESP32-S3
**Симптом:** Логічний аналізатор показував тривалість одного біта 208-209 мкс замість очікуваних 104 мкс (таймінги були збільшені рівно вдвічі).  
**Причина:** Драйвер `rmt_raw` розраховував дільник виходячи з базової частоти 80 МГц (`div = 80000000 / resolution`). Проте на ESP32-S3, при обраному налаштуванні `RMT_SCLK_SEL`, джерелом тактування був XTAL з частотою 40 МГц. Через це RMT працював удвічі повільніше.  
**Рішення:** Ми оновили формулу розрахунку дільника в `rmt_raw.c` на використання правильної частоти: `div = 40000000 / resolution_hz;`. Після цього 1 тік став дорівнювати рівно 1 мкс.

### 2. Неправильний Idle-рівень (стан спокою)
**Симптом:** На аналізаторі не було видно стартового біта, оскільки в стані спокою лінія перебувала в рівні LOW (0), і стартовий нуль просто зливався з фоном. Для UART стан спокою має бути HIGH (1).  
**Причина:** Під час ініціалізації драйвера на регістрах біт `RMT_IDLE_OUT_LV_CH0` (рівень спокою) примусово скидався в 0. Будь-які спроби "підтягнути" пін через `gpio_set_level` ігнорувалися, бо апаратний RMT перехоплював управління піном і тягнув його вниз.  
**Рішення:** Ми змінили ініціалізацію в `rmt_raw.c`:
`ch0conf0 |= (1 << 5); // Ставимо 1 в IDLE_OUT_LV для UART`  
Тепер лінія автоматично підтягується до HIGH між передачами.

## Як запустити тест
Зараз у `app_main` налаштований ідеальний тест для логічного аналізатора:
Кожні 200 мілісекунд відправляється байт `0x55` (у двійковому вигляді `01010101`). Оскільки рівні постійно чергуються, це дозволяє найточніше виміряти швидкість (baud rate) та впевнитися, що тривалість біта становить рівно 104 мкс.
